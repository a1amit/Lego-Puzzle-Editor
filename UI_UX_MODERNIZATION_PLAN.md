# UI/UX Modernization Plan - Lego Puzzle Editor

> Generated by a 4-agent expert team: UI Designer, UX Designer, Web Researcher, Frontend Engineer

---

## Executive Summary

The Lego Puzzle Editor has a strong technical foundation (React 19, Tailwind v4, shadcn/ui, Framer Motion, Three.js) and is approximately **80% polished**. No fundamental technology changes are needed. The gap to a modern, premium feel comes from consistency issues, missing onboarding, untapped animation potential, and accessibility gaps.

**Recommended Design Direction:** Dark Glassmorphism — frosted translucent panels over ambient gradient orbs. The 3D scene would look stunning through translucent panels.

## Phase 1: Quick Wins (1-2 hours)

Low-risk changes with immediate visual/UX impact.

### 1.1 Fix Muted Text Contrast (C1)

**File:** `src/index.css` (line 46)

```css
/* Before */
--muted-foreground: oklch(0.60 0.01 285);

/* After — passes WCAG AA */
--muted-foreground: oklch(0.67 0.01 285);
```

**Impact:** High | **Risk:** None | **Time:** 2 min

---

### 1.2 Consolidate Surface System (H1)

**File:** `src/index.css` (`:root` block)

Add 4 solid surface tokens to replace dozens of opacity variants:

```css
--surface-base: oklch(0.13 0.005 285);     /* page background */
--surface-raised: oklch(0.17 0.005 285);    /* card/panel bg */
--surface-overlay: oklch(0.20 0.005 285);   /* popovers, overlaid elements */
--surface-sunken: oklch(0.11 0.005 285);    /* inset areas, code blocks */
```

Then replace across components:
- `bg-card/65` `bg-card/25` `bg-card/55` -> `bg-[var(--surface-raised)]` or appropriate level
- `bg-secondary/50` `bg-secondary/60` `bg-secondary/80` -> solid secondary or surface-overlay

**Impact:** High | **Risk:** Low (visual review needed) | **Time:** 30 min

## Key Technical Notes

1. **Framer Motion v12.34.3 is already a dependency** but barely used — this is the single biggest untapped opportunity
2. **shadcn components are well-configured** with size variants (`xs`, `icon-xs`), tab variants (`default`, `line`) — leverage these
3. **The CSS token system is solid** (oklch, animation tokens, Lego brand colors) — extend it, don't replace it
4. **`useShallow` from Zustand** is already used in InventoryPanel but NOT in ValidationPanel or PuzzleInfoPanel — quick performance win
5. **The celebration popup is the gold standard** for animation quality — use it as the reference for patterns elsewhere
6. **Tailwind v4 features** (container queries, 3D transforms, `@theme` directive) are available but underutilized
